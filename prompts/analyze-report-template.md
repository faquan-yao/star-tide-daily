# 单仓库分析报告模板

每份报告写入 `STAR_TIDE_ROOT/artifacts/<date>/NN-owner-repo.md`，**必须**包含以下五节（标题保持一致）：

```markdown
# owner/repo

## 1. 项目用途

（解决什么问题、目标用户、核心能力；依据 README / docs / 仓库描述）

## 2. 安装方法

（可复现步骤：环境要求、依赖、安装/构建/启动命令；标注出处如 README、Dockerfile、package.json scripts）

## 3. 软件架构

（模块划分、技术栈、目录与入口说明）

```mermaid
flowchart TB
  %% 架构相关图：组件/模块/层次关系
```

## 4. 运行逻辑

（启动流程、主链路、关键调用关系）

```mermaid
flowchart TD
  %% 或 sequenceDiagram：执行/请求处理流程
```

## 5. 风险

（许可、安全、维护活跃度、依赖、文档缺失、推断不确定项等；每条一行或列表）
```

规则：

- **必须**包含 **2 个** `mermaid` 代码块（一节在「软件架构」，一节在「运行逻辑」）。
- 浅克隆下**不得编造**仓库中未出现的命令、模块或依赖；不确定处写入「风险」并说明依据不足。
- 图表节点命名与仓库实际目录/模块一致；无足够信息时在风险中说明，勿画空壳图。
